# 4STROKES 定着分析 — 「たまに役立つが、日常使いされない」要因と改善アプローチ

> 対象: main.html(4ガレージ×4ストローク)+ mandara.html(マンダラ+AI Insight)
> 分析日: 2026-07-10 / コードベース全体の静的調査に基づく

---

## エグゼクティブサマリー

4STROKESは「Key → Issue → Action → Publish の4段階で思考を進める」という着想自体が強く、
エディタ体験(自動保存・Markdown・URL展開・同期)も良質。にもかかわらず日常に定着しない理由は、
**アーキテクチャがそのまま利用パターンを規定しているため**である。

1. **容量が固定4スロット** — 蓄積できず、新しい思考のたびに過去を破壊する必要がある
2. **キャプチャが遅い** — 「今すぐメモしたい」を受け止める導線がない
3. **呼び戻す仕組みがゼロ** — 履歴・レビュー・通知・進捗が一切なく、開く理由が発生しない
4. **"Publish" が実体を持たない** — メソッドの報酬(成果の出口)が存在せず、完了体験がない
5. **Mandara がサイロ** — 構造化思考(Mandara)と日常面(ガレージ)が分断され、相互に呼び込めない

つまり「1〜4個のテーマをじっくり考えるとき(=たまに)」には最適だが、
「毎日書き溜め、見返し、外に出す」ループが構造的に閉じない。以下、証跡と改善策を詳述する。

---

## 1. 現状のユーザーフロー(実装ベース)

### 1.1 コアメモアプリ(4ガレージ)

1. `index.html` は `localStorage.storage_mode` を見て `main.html` / `login.html` へリダイレクトするだけ(`index.html:33-45`)。**初回訪問者は必ずログイン壁に着地**する。
2. `login.html` は6種の認証手段(メールリンク/パスワード/登録/リセット/Google/GitHub)を提示し、「ログイン不要のローカルモード」はページ最下部・2つの "OR" 区切りの下(`login.html:594-599`)。副題は「Authentication Required」(`login.html:437`)— 実際は必須でないのに必須に見える。
3. `main.html` は固定4ガレージ × 4テキストエリア = **16枠が全て**(`main.html:67-466`)。「新規作成」という概念はなく、枠に直接書く。
4. 自動保存は keyup 500ms デバウンス(`js/app.js:137-150`, `js/constants.js:8`)。URL貼り付けは unfurl.io 経由でMarkdownリンク化(`js/url-converter.js:18-50`)。
5. **"Publish" は4番目のテキストエリアのラベルに過ぎない**(`main.html:147-148`)。公開・共有・エクスポート・コピー等のアクションは一切存在しない(コア側で "publish" はラベル定数 `js/minimap.js:15` のみ)。
6. もう一つの動詞は「削除」のみ。ストローク単位・タイトル・ガレージ単位の削除が `confirm()`/`alert()` で提供され、キャンセル時も `alert("Cancelled")` が出る(`js/app.js:237-262,340-342`)。削除=空文字上書きで**履歴もUndoもない**(`js/storage-service.js:266-282`)。

### 1.2 Mandara

- 3×3(9セル)の単層マンダラ+タイトル+メモ(`js/mandara.js:145-189`)。本来の81マス(セル→サブチャート展開)は未実装。
- タグ・TODO(マンダラ内ローカル、`js/mandara-tags-todos-ui.js`)、リストビュー+検索+並べ替え(`js/mandara-list-view.js:44-59`)。
- AI Insight: 構造分析→課題抽出→アクションプランの3段+横断分析(`js/mandara-insight-controller.js:183-268`)。プロバイダは Gemini / OpenAI のみ、Claude はスタブ(`js/ai-providers.js:11-15`)。共有キー未設定環境では**ユーザー自身のAPIキー入力が必須**(`js/mandara-insight-api-tab.js:107`)。結果はメモリ5分キャッシュのみで**リロードで消える**(`js/mandara-insight.js:12`)。
- エクスポートは Insight レポートのMarkdownのみ(`js/mandara-insight-export.js`)。**マンダラ本体・ガレージ本体のデータエクスポートは非対応**(README-MODES.md:94-95)。

## 2. 「日常使いされない」要因分析

### 要因A: データモデルが「蓄積」を許さない(最重要)

- ストレージは固定16キー / 固定4 Firestoreドキュメント(`js/storage-service.js:116-125`, `js/firestore-crud.js:66-92`, `GARAGE.COUNT: 4` @ `js/constants.js:31-34`)。
- 5個目の思考を始めるには既存ガレージを**破壊**するしかない。削除は不可逆で、書いた記録すら残らない。
- `updatedAt` は毎保存で書かれている(`js/firestore-crud.js:111`)のに**どこにも表示されない**。「先週何を考えていたか」を見る手段がない。
- 日常使い=蓄積・検索・見返しであり、4スロット・スクラッチパッドはその対極。「たまに役立つ」体験(1〜4個の課題を深く考える)はこのモデルの想定通りの挙動。

### 要因B: キャプチャ(書き始めるまで)が遅い

- コールドスタート: リダイレクトページ → main.html → モジュール読込 →(オンライン時)認証復元待ち最大1.5秒(`js/app.js:686-703`)→ 目的ガレージへスクロール → 対象ボックスを探す。
- manifest.json はあるが **Service Worker が存在しない**(リポジトリ全体で `serviceWorker` 検索ヒット0)。オフラインシェルなし、share_target なし。オンラインモードで圏外だと Firestore 書込みは `console.error` に落ちるだけで**ユーザーに失敗が伝わらない**(`js/app.js:147-149`)。
- モバイル: ピンチズーム禁止(`main.html:6` `user-scalable=no`)、`100vh` 起因のiOSアドレスバー問題(`styles/_garage.scss:7,19`)、Mandaraは768px未満でも3カラム維持で約80px高のセルに日本語複数行を書く構造(`styles/_mandara.scss` モバイルブロック)。`js/mandara-view-prefs.js:3-4` 自身が「1マスが小さくて入りきらない」と認めている。
- 貼り付けは毎回 unfurl.io へのネットワーク往復を待つ(`js/app.js:155-164`)。プレーンテキスト貼付でも遅延し、オプトアウトはコード内フラグのみ(`js/constants.js:26`)。

### 要因C: 呼び戻し(リテンション)機構が全欠落

存在するもの: 自動保存表示、クロスデバイス同期、ショートカット+ミニマップ(`js/minimap.js`)、URL展開 — いずれも「開いた後」の品質。

欠落しているもの:

| 機構 | 状態 |
|---|---|
| 通知・リマインダー・レビュー促し | なし |
| 履歴/タイムライン(updatedAt表示含む) | なし(データはあるが未表示) |
| Key→Issue→Action→Publish の進捗状態 | なし(4段階は単なるラベルで、ステートマシンではない) |
| 完了成果の出口(コピー/エクスポート/共有) | コア側なし("Publish"は空箱) |
| 横断TODOダッシュボード | なし(TODOは各マンダラ内に閉じる) |
| ストリーク/統計 | なし |

**ループが閉じない**: キャプチャは遅く、レビュー手段はなく、完了は「何も起きないPublish欄」か「破壊(削除)」の二択。

### 要因D: "Publish" の空洞化 — メソッドの報酬不在

アプリの名前を冠する4段階の最終ステップが、単なる4番目のテキストエリア。
思考をやり切っても**何も出力されず、達成が形にならない**。皮肉にも Mandara Insight 側にはコピー/MDダウンロードが実装済み(`js/mandara-insight-export.js:268-301`)で、コアの看板フローだけが出口を持たない。
習慣形成論(トリガー→行動→**報酬**→投資)の報酬が欠けており、「使い切った感」が発生しないため再訪動機が育たない。

### 要因E: Mandara とコアのサイロ化

- 相互リンクはナビ1本ずつ(`main.html:43` ⇄ `mandara.html:38`)。データは別コレクションで、メモ側からマンダラのタグ・TODO・内容は一切見えない。
- 唯一のブリッジは「AI Insightのアクションプラン→ガレージ書き込み」だけで、しかも `prompt("A/B/C/D")` による**生ダイアログでの上書き**(`js/mandara-insight-controller.js:330-349`)。AIを実行しない限りブリッジ自体が存在しない。
- `linkedGarageId` は作成時に書かれるが**どこからも読まれないデッドエンド**(`js/mandara-logic.js:31`, `mandara-insight-controller.js:360`)。
- 頻度(メモ)と構造(マンダラ)が互いの強みを渡せない: メモ側は頻度があっても構造・バックログがなく、マンダラ側は構造があっても開く頻度が生まれない。

### 要因F: 初回体験と信頼性の摩擦

- オンボーディングが「最初のメモ」ではなく「認証の選択」。Key/Issue/Action/Publish の意味説明・ツアー・プレースホルダ文なし。タイトル欄は初期値 `value="stroke-title1"` という**ゴミに見えるデフォルト値**を持つ(`main.html:74`)。
- Googleログインは `CONFIG.ALLOWED_GOOGLE_EMAIL` の**単一メール許可リスト**で他者を拒否(`js/auth.js:95-100,180-184`, GOOGLE_AUTH_RESTRICTION.md)。
- ローカル/オンラインは**別データセット**で、切替時に見える内容が変わるが説明はない。移行は初回ログイン時の一方向のみ(`js/app.js:729`)。
- AI Insight は共有キー未設定だとAPIキー取得という開発者向けハードルが立つ(`docs/MANDARA_INSIGHT_TODO.md` §1 は本番env未設定を「今すぐ対応が必要」と明記)。
- 実行時CDN依存(marked/DOMPurify @ `js/markdown-renderer.js:6-7`、廃止済み bundle.run のポリフィル @ `main.html:25`、picsum.photos のログイン背景 @ `login.html:69`)、`main.html:2` の `<html lang="ja"></html>`(html要素が2行目で閉じている)などの品質瑕疵も、無意識の信頼低下に寄与。

## 3. 改善アプローチ(優先度つきロードマップ)

### 原則

「日常使い」= **①秒で書ける → ②溜まる → ③戻る理由がある → ④出口(報酬)がある** の4点をこの順で閉じる。
ビジュアルの磨き込みより先に、上記ループの欠落を埋める。

### Phase 1 — 構造的ボトルネックの解消(効果: 最大)

1. **ガレージの無制限化+アーカイブ**
   - 固定4スロット(`GARAGE.COUNT`)を「アクティブ4 + 無制限アーカイブ」に再設計。既存の4枠UIは「作業台」として維持しつつ、「Del」を「Archive」に置換(破壊→蓄積へ)。
   - Firestoreは既にドキュメント指向なので拡張は自然(`garages/{id}` をコレクション化)。`updatedAt` を一覧・各ガレージに表示。
   - リストビュー+検索は Mandara 側の実装(`mandara-list-view.js`)をほぼ流用可能。
2. **"Publish" を実アクションにする**
   - Publish 欄の隣に「Publish」ボタン: Markdownコピー / .mdダウンロード / (将来)共有URL。実装は `mandara-insight-export.js:268-301` の移植で小コスト。
   - Publish 実行でガレージを「完了」状態にしてアーカイブへ送る = 完了体験と蓄積を同時に作る。
3. **4段階をステートマシン化(軽量に)**
   - 各ガレージに現在ステージ(Key/Issue/Action/Publish)のインジケータと「次のステージへ」導線。進捗が可視化されるだけで放置ガレージが「呼び戻しトリガー」に変わる。

### Phase 2 — キャプチャ速度とモバイル(効果: 大)

4. **クイックキャプチャ導線**
   - 起動即・単一テキストボックスの「Inbox」(書いたら後で任意ガレージのKeyへ振り分け)。リダイレクトページを廃し、認証復元を待たずに入力可能にする(保存はキュー)。
5. **Service Worker 導入で本物のPWAに**
   - オフラインシェル+書込みキュー(オンライン復帰時フラッシュ)、manifest に `share_target` を追加してOSの共有シートから直接キャプチャ。
   - オフライン時の保存失敗を console ではなくUIに出す(`js/app.js:147-149` の握りつぶし解消)。
6. **モバイル編集の再設計**
   - `user-scalable=no` の撤廃、`100vh`→`100dvh`。Mandara はモバイルで1セル拡大編集(タップでフォーカスモード)。
   - `alert/confirm/prompt` を既存のモーダル/トースト(`main.html:707-730`)に統一。

### Phase 3 — 呼び戻しループ(効果: 大、Phase1が前提)

7. **横断TODO/レビューダッシュボード**
   - 全マンダラのTODO+Insight提案TODOを main.html 上部に「Today」パネルとして集約。各項目からマンダラ/ガレージへ戻れる = 毎日開く理由の創出。
8. **週次レビュー機構**
   - 「今週触ったガレージ/マンダラ」「Action止まりの項目」を自動リスト化。任意でメール/プッシュのリマインダー(Firebase Messaging か、まずはカレンダー .ics 出力の低コスト案)。
9. **Insight結果の永続化**
   - 分析結果(JSON)をマンダラオブジェクトに保存し、時系列で比較表示。「前回の計画 vs 完了チェック」が自然な週次レビューフックになる(5分キャッシュ問題の解消)。

### Phase 4 — サイロ解消と体験の統合

10. **ガレージ⇄マンダラの双方向ブリッジ**
    - `linkedGarageId` を実際に読み、両側にバッジ/バックリンク表示。「ガレージをマンダラに昇格」「マンダラのセルをガレージ化」を prompt() でなくピッカーUIで。
11. **AIの初回体験からキー入力を排除**
    - 共有キーのenv整備(TODO §1)またはサーバサイドプロキシ(Vercel Functions)。キーなしユーザー向けローカル分析の質を上げる(現状は空セル検出+文字数バランスのみ @ `js/mandara-local-analyzer.js`)。

### Phase 5 — 品質・信頼の下地(随時)

12. オンボーディング: 初回起動時に4段階メソッドの30秒ツアー+各欄にプレースホルダ文(「例: なぜ〜が気になるのか?」)。初期値 `stroke-title1` を placeholder 属性へ。
13. `main.html:2` の破損マークアップ修正、CDN依存のローカルバンドル化(bundle.run は廃止済み)、貼り付け時URL展開のオプトアウトUI化、グローバル共有 `saveTimer`(`js/app.js:39`)のフィールド単位化(高速連続編集での保存取りこぼし防止)。
14. データエクスポート/インポート(JSON一括)— 「消えるかもしれない」不安の解消はローカルモードの信頼に直結。
15. 死蔵コードの整理: `mandara-store.js`(未使用Pub/Subストア)、設定内「Swap Garage Data」(コード自身が非推奨と明記 @ `js/settings.js:21,33`)。

## 4. 優先順位の考え方(まとめ)

| 優先 | 施策 | 解消する要因 | 実装コスト感 |
|---|---|---|---|
| ★1 | ガレージ無制限化+アーカイブ | A(蓄積不能) | 中(Mandaraリスト実装を流用) |
| ★2 | Publish の実アクション化 | D(報酬不在) | 小(既存export移植) |
| ★3 | クイックキャプチャ+SW/share_target | B(キャプチャ遅) | 中 |
| ★4 | 横断TODO「Today」パネル | C(呼び戻しゼロ)/E(サイロ) | 中 |
| ★5 | Insight永続化+週次レビュー | C | 中 |
| ★6 | モバイル編集再設計 | B | 中 |
| ★7 | AIキー壁の除去 | F | 小〜中(env整備 or proxy) |

★1と★2だけでも「たまに役立つスクラッチパッド」から「溜まっていく思考システム」への転換点になる。
★3〜★5で日次ループ(書く→溜まる→戻る→出す)が閉じ、初めて「日常のアプリ」になり得る。
